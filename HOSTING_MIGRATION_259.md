# Hosting migration — Phase 1: SQLite → Postgres (LOCAL, ISOLATED) — #259

**No production cutover. Production still runs on SQLite/Tailscale, untouched.** This
phase proves the app can run on Postgres and that the data migrates row-for-row. The
live `superstars.db` was only ever READ (via a snapshot copy).

## `SSC_DB_URL` — the one knob (db_layer.py)

Every connection routes through `db_layer.connect()`:

| `SSC_DB_URL` | backend |
|---|---|
| _unset_ or `sqlite` | **SQLite** (DEFAULT — production path, byte-for-byte: 60s timeout, `Row`, WAL + busy_timeout) |
| `sqlite:///C:/path/copy.db` | SQLite against an **isolated copy** (test-isolation: gate never touches live) |
| `postgresql://user@host:port/db` | **Postgres** via psycopg v3 (wrapped to present the sqlite3 interface) |

`server.db()`, `auth._db()`, and the routed smokes all call `db_layer.connect()`.
Default is SQLite, so production is unaffected and we keep a safety net.

## Dev Postgres (throwaway; NOT production) — no admin, no Docker

## Data migration — `migrate_sqlite_to_pg_259.py` (READ-ONLY on SQLite)

`python migrate_sqlite_to_pg_259.py <snapshot.db> <postgres_url> --reset`

Introspects the snapshot, translates DDL, loads every table (ids preserved, FK order),
resolves FK orphans, adds FKs, resets sequences, and verifies per-table counts.
**Verified: 73 tables row-for-row SQLite==Postgres** (spot-checks: 1 project, 35 drops,
385 stage rows, 18 employees, 22 worker_rates, 1 real admin + 3 is_system fixtures),
with the only deltas on the two FK-orphan-cleaned tables.

## Dialect changes handled

- **Placeholders**: `?` → `%s` via a proper adapter that ALSO doubles literal `%` to
  `%%` (so `LIKE '%foo%'` survives; a `?` inside a string literal is left alone).
- **lastrowid**: `cursor.lastrowid` → `INSERT ... RETURNING <pk>` (pk looked up from
  pg_catalog); literal `last_insert_rowid()` in SQL → `lastval()`.
- **Upserts**: `INSERT OR IGNORE` → `... ON CONFLICT DO NOTHING`.
- **Booleans**: kept as INTEGER 0/1 everywhere (consistent on both backends — no churn).
- **Dates**: stored as **TEXT/ISO (LOCAL, never UTC)** on BOTH backends — date columns
  declared TIMESTAMP/DATE in SQLite are created as **TEXT** in Postgres so psycopg returns
  strings (the app compares dates as strings). `DEFAULT CURRENT_TIMESTAMP` → `(now())::text`.
- **Auto-increment**: `INTEGER PRIMARY KEY AUTOINCREMENT` → `INTEGER GENERATED BY DEFAULT
  AS IDENTITY`; sequences `setval()` to `max(id)` after load.
- **Generated cols**: `GENERATED ALWAYS AS (...) VIRTUAL` → `STORED`.
- **PRAGMAs**: no-op on Postgres.
- **Views**: `GROUP_CONCAT` → `string_agg`, `IFNULL` → `COALESCE`.

## FK violations resolved (the FK-enforcement-OFF finding)

SQLite ran with FK enforcement OFF (server.db()), so deleting test-fixture users over
#257/#258 left **49 orphaned child rows** referencing now-deleted `users.id`. Postgres
ENFORCES FKs, so these were resolved on load (documented, not silently dropped):

| child | fk | orphans | resolution |
|---|---|---|---|
| login_audit | user_id → users.id | 34 | NULLed (nullable) — rows kept |
| audit_log | actor_user_id → users.id | 2 | NULLed (nullable) — rows kept |
| sessions | user_id → users.id | 12 | DELETED (NOT NULL) — orphan sessions |
| role_change_audit | user_id → users.id | 1 | DELETED (NOT NULL) |
